# SDK Maintainer Rules

## Publishing to npm — STRICT RULES

**Never run `npm publish` for README, docs, or comment-only changes.**

Only publish when `src/` has actual code changes.

### Correct release flow (code changes only):
```bash
npm version patch        # bumps package.json + auto-creates git tag
git push && git push --tags
npm publish
```

### README/docs only:
```bash
git commit -m "..."
git push
# STOP. Do not run npm publish.
```

## Versioning
- Version is managed via `npm version patch/minor/major` — never edit package.json version manually
- Every npm publish must have a corresponding git tag (npm version creates this automatically)
- Current published version: check `npm show @fortsignal/sdk version`

## What lives here
- `src/` — SDK source (TypeScript). Only changes here warrant a new npm version.
- `dist/` — built output, generated by `npm run build` (runs automatically via prepublishOnly)
- `README.md` — public docs. Edit freely, push to GitHub, never triggers a publish.

## What does NOT live here
- The FortSignal API (fortsignal-api) — that's a separate Cloudflare Workers project, deployed via `npx wrangler deploy`
- Dashboard, composer, demo — all part of fortsignal-api, not this repo
